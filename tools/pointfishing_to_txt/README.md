# pointFishingDB → RAG TXT 변환기

`pointFishingDB/`의 원본 데이터를 RAG(Chroma) 적재용 TXT로 변환한다.
결과물은 `pointFishingDB_txt/` 에 생성된다.

## 실행

```bash
cd tools/pointfishing_to_txt
python build_ban.py     # 01 지자체 낚시금지구역
python build_rest.py    # 02~10 나머지 전부
python build_index.py   # 00 안내/용어 색인
python verify.py        # 원본 셀 누락 검증 + 산출물 통계
```

## 변환 규칙

- **인코딩**: 원본은 cp949 / utf-8-sig가 섞여 있다. 자동 판별해 읽고, 산출물은 전부 UTF-8
  (`main.py`의 `TextLoader(encoding="utf-8")` 요구사항).
- **헤더 정리**: cp949로 저장되며 깨진 UTF-8 BOM 잔재(`癤용굾﻿낚시금지구역명`)를 제거한다.
- **레코드 = 청크**: 원본 1행이 빈 줄로 구분된 1개 단락이 된다. `main.py`의
  `RecursiveCharacterTextSplitter(separators=["\n\n", "\n", ".", " "])`가 `\n\n`을 먼저 쪼개므로
  단락이 그대로 하나의 청크가 된다. 6,415개 단락 중 500자를 넘는 것은 16개(0.25%)뿐이다.
- **자기완결성**: 각 단락 첫 줄에 `[유형] 행정구역 명칭`을 넣어, 청크 하나만 검색돼도
  어느 지역 무엇에 대한 정보인지 알 수 있다.
- **좌표 변환**: 원본 공간정보(EPSG:5179, Korea 2000 / Unified CS)를 WGS84 위경도로 변환한다
  (`tmk.py`, 순수 파이썬 역 횡메르카토르). 원본에 도분초 좌표가 함께 있는 행으로 검증했고
  소수점 6자리까지 일치한다.
- **값 보존**: `verify.py`가 원본의 비어있지 않은 셀 53,847개를 전부 산출물에서 재확인한다
  (현재 누락 0건).

## 주의

`04_낚시터_전국.txt`만 낚시터 1곳당 `[낚시터]`(위치·어종·요금)와
`[낚시터 시설·이용정보]`(시설·관리기관) 두 단락으로 나뉜다. 컬럼이 24개라 한 단락에 담으면
청크 크기를 넘기기 때문이다.
